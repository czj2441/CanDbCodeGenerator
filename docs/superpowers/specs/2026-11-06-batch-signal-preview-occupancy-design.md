# 批量信号创建预览：显示已有信号占用层

## 意图与动机

`BatchModal.vue`（批量创建信号）的右侧预览目前只渲染本次要新建的信号，用户看不到当前报文已有信号，
无法在创建前判断「新信号会不会压到已有信号、哪里还有空位」。重叠目前要等创建后才由
`validate_all_signals` 非阻断报出，属于事后补救。

用户明确只需要「避让 + 找空位」判断，不需要看清已有信号的名称与完整布局，也不希望预览区因此变复杂。

## 目标

- 在批量创建预览中，以最小视觉复杂度呈现「已有信号占用」与「新建信号」的位布局关系。
- 新信号与已有信号的重叠在创建前即可见。
- 空闲位一目了然。

## 非目标 / 反目标

- 不在预览中显示已有信号的名称标签、逐信号分色（避免新旧同色、标签拥挤）。
- 不合并预览下方表格（表格仍只列新建信号）。
- 不改变 `computeBatchSignals` 的布局计算规则，也不引入后端改动。

## 约束

- 预览区宽 380px，画布 `max-height: 280px`，空间有限，新增内容必须是「底图层」而非「同框完整信号」。
- `BitLayoutCanvas` 已支持多信号与重叠红斜线（`computeCellMap` 的 `overlapBits`）。
- 已有信号数据已在 `editor.selectedMessage.signals`，字段格式与新建信号一致
  （`start_bit` 为存储 MSB、`length`、`byte_order`），可直接复用 `getSignalBits` 计算占用 bit 集合。

## 方案（择 1）

1. **灰底占用层（已选）**：已有信号统一渲染为半透明灰色底图，只填占用的 bit 格子，不分色、不标名；
   新信号保持彩色 + 名字标签；重叠格沿用红斜线；空闲位为空白格。
2. 只加一行摘要数字（新信号 N bit · 重叠 M bit · 空闲 K bit）：零视觉负担，但看不到空位位置，不满足需求。
3. 已有信号与新信号同框完整绘制：信息最全，但正是用户担心的预览变复杂。

## 已决定的实现要点

- 在 `BitLayoutCanvas` 增加一个可选 prop（拟命名 `backgroundSignals`，或直接 `occupiedBits`），
  接收「已有信号」并渲染为灰色半透明占用层（不参与 `signalLabels`）。
- 重叠检测需覆盖「新建信号 cell ∩ 已有占用 bit」：把背景占用 bit 并入重叠计算，使红斜线也能标出
  新旧重叠格（现有 `computeCellMap` 只对 `signals` 内部做重叠检测，需要扩展或另算交集）。
- `BatchModal.vue` 把 `editor.selectedMessage` 的已有信号传给画布作为背景；下方表格不变。
- 本次不做「悬停灰块提示它属于哪个已有信号」的 hover（记为可选后续增强）。

## 留给实现者

- `occupiedBits` 的具体形态：作为 `Set<number>` 直接传入，还是作为信号数组由画布内部换算；
  倾向 `Set<number>`，与画布解耦、避免重复计算。
- 灰色底图的具体配色/透明度，沿用现有主题变量（如 `--text-dim` / `--border-light` 的低透明态）。
- 背景占用层与 `startBitOverrides`、`highlightNames`、拖拽等现有 prop 的交互：预览场景这些均不启用，
  保证不回归即可。
